# Task 3 — Нотатки й вартість

**Застосунок:** Workday Time Tracker — особистий трекер робочого часу.
**Стек:** Next.js 16 (App Router) + React 19 + TypeScript.
**Дизайн-система:** Porsche Design System v4 (`@porsche-design-system/components-react`, підшлях `/ssr`).
**Інструмент:** Claude Code, модель Claude Opus 5.

---

## 1. Що вийшло з першого промпту, а що ні

**Вийшло одразу:**

1. **Модель даних лягла з першої спроби і не змінювалася потім.** Ключове
   рішення — «таймер, що йде, — це і є незакрита сесія» (`endedAt === null`),
   без окремого поля `activeTaskId`. З цього одного інваріанта («не більше
   однієї сесії з `endedAt === null`») безкоштовно випливають три вимоги ТЗ:
   «лише одна задача одночасно», «старт іншої задачі зупиняє поточну» і
   «переживає перезавантаження». Статус задачі (`idle`/`running`/`paused`/
   `done`) не зберігається, а обчислюється — тому він не може розійтися з
   даними.
2. **Каркас Next.js + PDS завівся без жодної правки.** `create-next-app`,
   `npm i @porsche-design-system/components-react`, провайдер у `layout.tsx`,
   імпорт глобального CSS — і `npm run build` пройшов з першого разу.
3. **Верстка з токенів дизайн-системи.** Уся layout-CSS написана виключно на
   CSS-змінних PDS (`--p-spacing-*`, `--p-color-*`, `--p-radius-*`). Побічний
   ефект, якого не планували: **темна тема запрацювала сама** — клас
   `scheme-light-dark` перемикає і компоненти, і власну розмітку разом.

**Не вийшло з першого разу:**

4. **Знання про PDS виявилися застарілими на цілу мажорну версію.** У v4
   більше немає `p-text-field-wrapper`, `p-flex` і `p-grid` — замість першого
   тепер `p-input-text`, а layout-компонентів немає взагалі. Якби писали «з
   пам'яті», зламалося б усе.
5. **Перша реалізація персистентності не пройшла лінтер.** Класична зв'язка
   `useState` + `useEffect` для читання `localStorage` після монтування
   впирається в правило React Compiler `react-hooks/set-state-in-effect`.

## 2. Де агент спіткнувся і як розвернули

**a) Застарілий API дизайн-системи.**
Сайт документації PDS — це JS-SPA, тож `WebFetch` повертає порожню сторінку
(перевірено — прийшов лише `<title>`). Розворот: **читати не документацію, а
сам пакет**. У `node_modules/@porsche-design-system/components-js/skills/`
лежить повний довідник, який версійно точно відповідає встановленому пакету
(4.6.0) — включно з переліком компонентів, іменами іконок, слотами `p-modal` і
списком CSS-змінних. Плюс `.d.ts`-типи як остаточне джерело правди про пропси.
Це швидше й надійніше за будь-який пошук в інтернеті.

**b) `react-hooks/set-state-in-effect`.**
Спокуса — додати `// eslint-disable`. Замість цього переписали на
`useSyncExternalStore` — канонічний React 19 API для читання зовнішнього
сховища. Виграш подвійний: лінтер чистий **і** зник ручний прапорець «чи ми вже
змонтувалися», бо React сам використовує `getServerSnapshot` для SSR і першого
рендера гідратації. Правило лінтера тут вказало на реально кращу архітектуру, а
не просто на стиль.

**c) Хибна тривога у власному тесті.**
Playwright-скрипт додавав три задачі підряд без пауз і не знаходив рядки —
виглядало як баг застосунку. Замість того щоб «чинити» робочий код, написали
окремий діагностичний скрипт: виявилося, що Enter у `p-input-text` працює
коректно (компонент `formAssociated`, тому неявний submit проходить крізь межу
Shadow DOM), а гонку створював сам тест. **Урок: спершу довести, що баг є.**

**d) Помилка була в моєму твердженні, а не в коді.**
Одна з 38 перевірок доменної логіки впала на «сума за день = 40 хв».
Перерахунок вручну показав, що правильно 50 хв — помилилися в очікуваному
значенні, код був правий. Інваріант, який справді щось перевіряє («сума по
задачах == загальна сума за день»), проходив увесь час.

**e) Пастка Windows із `AGENTS.md` спрацювала буквально.**
`npx repomix --output /dev/null` під Git Bash створив у `app/` реальний файл з
іменем `nul`. Видалити його вдалося лише через
`cmd /c del "\?\D:\...\app\nul"`.

**f) `next dev` сам генерує `app/AGENTS.md` і `app/CLAUDE.md`** і додає їх
назад при кожному запуску. Файл сам пише, що його треба комітити, інакше
робоче дерево ніколи не буде чистим.

Зверніть увагу на структуру: **97,8 % — це cache read**. Агентна сесія — це не

величини за ціною.

> залежать від тарифу підписки, тому тут наведено первинні дані (токени), а не
> похідну оцінку.

**Розмір контексту та коду**

| Показник | Значення |
|---|---:|
| `npx repomix` в `app/` | **28 файлів, 13 862 токени, 50 207 символів** |
| Власного коду (`app/src`) | **1 277 рядків** у 15 файлах |

типів, перевірку припущень, запуск браузера, ітерації.

## 4. Спостереження

**1. Найдешевший спосіб дізнатися API — прочитати встановлений пакет, а не
шукати в інтернеті.**
Сайт документації не парсився, пошук дав відповіді для v3 (застарілі на цілу
мажорну версію), а правильна відповідь лежала в `node_modules` — версійно
точна за визначенням. PDS v4 навіть спеціально кладе туди `skills/`-довідник.
Наступного разу перший крок при роботі з незнайомою бібліотекою — `ls
node_modules/<pkg>` і `.d.ts`, а не веб-пошук.

**2. «Компілюється» ≠ «працює». Різницю ловлять три різні перевірки.**
`npm run build` пройшов з першого разу — і не сказав нічого про те, чи
перемикаються задачі одним кліком. Реальну впевненість дали три незалежні
шари: 38 перевірок чистої доменної логіки (правила таймера), прогін у
справжньому браузері через Playwright (Enter, перемикання, перезавантаження,
підтвердження очищення) і **перегляд скріншотів очима** — саме він виявив, що
`<p>` таймера тягне дефолтні браузерні `margin` і розриває картку порожнечею.
Жоден автотест цього не побачив би.

**3. Правило лінтера буває підказкою про архітектуру, а не бюрократією.**
`set-state-in-effect` легко було заглушити коментарем. Виконана натомість
вимога привела до `useSyncExternalStore` — менше коду, немає ручного прапорця
гідратації, немає ризику розбіжності SSR і клієнта. Якщо наступного разу
з'явиться спокуса написати `eslint-disable` — спершу варто витратити п'ять
хвилин на те, щоб зрозуміти, від чого правило захищає.

**4. Що зробив би інакше:** одразу зафіксував би у промпті версії стека
(Next 16, React 19, PDS **v4**). Експеримент із Task 4 показав це кількісно:
той самий агент без згадки про дизайн-систему видав 409 рядків голого HTML
замість 57 рядків на компонентах PDS — не через брак старанності, а тому що
фізично не міг вгадати контекст. Деталі — у
[`ab-experiment.md`](./ab-experiment.md).
